# Photo Manager Roadmap

本文档用于管理项目后续迭代，按优先级给出可执行任务、目标和验收标准。

## 目标

- 提升稳定性与可维护性
- 保持大图库场景下的性能体验
- 逐步降低 `main.js` / `renderer/app.js` 的维护成本

## 优先级说明

- P0：必须优先完成，直接影响稳定性或后续开发效率
- P1：重要优化，提升体验和长期可维护性
- P2：增强项，可在 P0/P1 稳定后推进

## 当前里程碑

### Milestone 1（P0）：工程基线稳定

1. 补齐关键开发文档（已开始）
   - [x] `README.md`
   - [x] `docs/ROADMAP.md`
   - [ ] `docs/ARCHITECTURE.md`（模块关系与主流程图）

2. 统一运行环境
   - [ ] 明确 Node/Electron 推荐版本组合
   - [ ] 原生模块重编译步骤固化（故障排查文档）

3. 错误可观测性
   - [ ] 主进程关键异常落日志（扫描、缩略图补全、哈希任务）
   - [ ] Web 服务启动/停止和异常日志结构化

验收标准：

- 新同学按文档 15 分钟内可启动项目
- 出现原生模块错误时可按文档快速恢复
- 重任务失败时能从日志定位到阶段和文件

### Milestone 2（P1）：拆分大文件，降低改动风险

1. 拆分 `src/renderer/app.js`
   - [ ] `state/`：状态与派生状态
   - [ ] `features/preview/`：预览、缩放、轮播
   - [ ] `features/settings/`：设置页与持久化同步
   - [ ] `features/duplicates/`：重复图片视图与交互

2. 拆分 `src/main.js`
   - [ ] `ipc/`：IPC 注册集中管理
   - [ ] `tasks/`：扫描、缩略图补全、哈希任务
   - [ ] `platform/`：托盘、快捷键、窗口行为

验收标准：

- 单文件不超过 1200 行（逐步达成）
- 新功能改动可集中在 1-2 个模块内完成
- IPC handler 能按功能分组快速定位

### Milestone 3（P1）：性能与体验优化

1. 扫描性能
   - [ ] 输出阶段耗时（enumerate/process/commit/cleanup）
   - [ ] 大目录场景下 UI 卡顿点排查

2. 列表与预览体验
   - [ ] 提升大分页切换响应
   - [ ] 预览切图与缩放操作流畅度优化

3. 重复图流程
   - [ ] 哈希任务可中断/恢复体验优化
   - [ ] 分组加载与展开策略优化

验收标准：

- 10 万+图片库下核心操作保持可用
- 扫描和哈希期间 UI 主交互不明显阻塞

### Milestone 4（P2）：发布与运维能力

1. 打包发布流程
   - [ ] 明确安装包输出方案（Windows）
   - [ ] 版本号与更新日志规范

2. 数据安全
   - [ ] 数据库备份与恢复说明
   - [ ] 高风险操作前确认与回滚提示

验收标准：

- 可以稳定产出可分发版本
- 用户数据迁移和恢复有明确路径

## 风险与控制

- 风险：大文件拆分过程引入行为回归  
  控制：分阶段拆分，每阶段只做“结构迁移，不改逻辑”

- 风险：原生模块环境差异导致开发阻塞  
  控制：统一 Node 版本并保持 `rebuild-native` 流程可复现

- 风险：重任务期间 UI 响应下降  
  控制：增加阶段日志和采样指标，先定位再优化
