# Aurora Gallery / 拂晓图库 — 版本更新计划

> 基于 `docs/ROADMAP.md` 的 P0/P1/P2 任务分层，结合 SemVer 语义化版本规范制定。
> 当前版本：`1.0.3`（2026-05-07）

---

## 版本节奏

| 类型 | 周期 | 说明 |
|------|------|------|
| **Patch** (`1.0.x`) | 1–2 周 | 稳定性修复、日志治理、文档补齐、小优化 |
| **Minor** (`1.x.0`) | 4–6 周 | 新功能、性能改进、体验优化、架构重构 |
| **Major** (`x.0.0`) | — | 破坏性变更（当前阶段暂不考虑） |

## 1.2.0 — 架构重构（预计 2026-07-20）

**目标**：拆分大文件，降低 `main.js` / `renderer/app.js` 的维护成本，提升可测试性。

### 任务清单

- [ ] **拆分 `src/main.js`**
  - `ipc/`：IPC 注册集中管理
  - `tasks/`：扫描、缩略图补全、哈希任务
  - `platform/`：托盘、快捷键、窗口行为
- [ ] **拆分 `src/renderer/app.js`**
  - `state/`：状态与派生状态
  - `features/preview/`：预览、缩放、轮播
  - `features/settings/`：设置页与持久化同步
  - `features/duplicates/`：重复图片视图与交互
- [ ] **模块边界文档化**
  - 补充模块间事件流与依赖说明
  - 更新 `docs/ARCHITECTURE.md`

### 验收标准

- 单文件不超过 1200 行（逐步达成）
- 新功能改动可集中在 1–2 个模块内完成
- IPC handler 能按功能分组快速定位
- 拆分过程不引入行为回归（结构迁移，不改逻辑）

## 版本号管理规范

1. **发布前检查单**
   - [ ] `package.json` `version` 已更新
   - [ ] `CHANGELOG.md` 已追加该版本条目
   - [ ] `README.md` `Current release` 已同步
   - [ ] 应用内 "About" 文案已同步（如有硬编码）
   - [ ] Git tag 已打（格式 `v{version}`，如 `v1.0.4`）
   - [ ] GitHub Actions 构建通过并上传 Release

2. **分支策略**
   - 常规开发：`main` 分支直接推进
   - 版本发布：从 `main` 打 tag，触发 CI 构建
   - 热修复：如需对旧版本补丁，从对应 tag 切 `hotfix/x.x.x` 分支

3. **CHANGELOG 格式**
   - 遵循 [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
   - 中英双语并存（与现有风格保持一致）

## 风险与控制

| 风险 | 影响版本 | 控制措施 |
|------|----------|----------|
| 大文件拆分引入行为回归 | 1.2.0 | 分阶段拆分，每阶段只做“结构迁移，不改逻辑”；拆分后跑全量冒烟测试 |
| 原生模块环境差异导致开发阻塞 | 全部 | 统一 Node 版本（`>=22.0.0 <23.0.0`）并保持 `rebuild-native` 流程可复现 |
| 重任务期间 UI 响应下降 | 1.1.0 | 增加阶段日志和采样指标，先定位再优化 |
| 版本号文档漂移 | 全部 | 发布检查单强制校验；长期可引入脚本自动同步 |
