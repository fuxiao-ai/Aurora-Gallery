# 与 Lap 项目功能对比及更新计划

日期：2026-09-27
对比对象：[julyx10/lap](https://github.com/julyx10/lap)（Tauri + Rust + Vue，本地优先照片管理器，GPL-3.0）
本项目：Aurora Gallery / 拂晓图库（Electron + 原生 JS，本地优先照片库，MIT）

> 说明：本文只做功能层面对比与排期建议，不引入 Lap 源码或依赖。实现仍按本项目 Electron / 原生 JS 结构独立完成。

---

## 一、定位差异（先看这个，避免盲目对标）

| 维度 | Lap | 拂晓图库 |
| --- | --- | --- |
| 运行时 | Tauri + Rust（体积小、内存占用低、原生性能强） | Electron + Node（生态成熟、Web 复用度高、打包体积大） |
| 核心场景 | 桌面本地浏览与整理（单机） | 桌面 + 局域网/公网 Web 访问（含手机端） |
| 技术栈 | Vue + Vite + Tailwind + daisyUI | 原生 JS + 自研 CSS |
| 平台 | macOS / Windows / Linux | Windows / macOS |
| 许可 | GPL-3.0-or-later | MIT |
| 组织模型 | 文件夹优先 + Collections/Tags/Ratings/Culling/Smart Albums | 文件夹优先 + 收藏/Favorites；组织元数据薄弱 |
| AI | CLIP 图文检索、InsightFace 人脸、ONNX Runtime | SigLIP 2 图文检索、YuNet+SFace 人脸、ONNX Runtime |

关键结论：**Lap 的强项集中在「组织与元数据」和「文件操作闭环」；本项目在「AI 能力」和「Web / 远程访问」上已经反超。** 因此差距清单应聚焦组织层与文件层，而不是重新造 AI 轮子。

## 三、不足清单（按优先级）

> 分级口径：P0 = 组织闭环缺失、数据模型简单、收益高成本低；P1 = 体验与检索增强、中等成本；P2 = 高风险或高成本、需专项设计。

### P0（组织能力缺口，最该补）

1. **评分（星级 1–5）缺失。** 现状：`photos` 表只有 `is_favorite`。影响：无法按质量筛选/排序，是智能相册的前置条件。
2. **挑选 / 拒绝标记（Culling）缺失。** 影响：大批量筛选工作流（连拍、旅拍）无法闭环。
3. **标签（Tags）缺失。** 影响：无法做跨目录的自由分类，也无法驱动智能相册。
4. **集合（Collections）缺失。** 影响：只能靠收藏和文件夹，缺少非破坏性的临时分组能力。
5. **智能相册缺失。** 影响：筛选组合无法保存复用，浏览入口是"固定几张"而非"可自定义视图"。

### P1（检索与体验增强）

6. **浏览维度不足：无地点 / 相机 / 镜头筛选。** 现有筛选只有媒体类型、尺寸、时间、目录、收藏。
7. **缩略图尺寸上限过低（最大 320 px，Lap 到 1024 px）。** 高分屏网格清晰度受限。
8. **缩略图/预览渲染方式不可配。** 无法选择 RAW 渲染或相机内嵌预览。
9. **重复清理缺少可回收空间汇总与批量删除。** 现有分组可用，但清理闭环不完整。
10. **浏览排序无"全量随机"。** 目前随机仅作用于幻灯片。
11. **无评论/备注字段。**
12. **AI 向量检索无 ANN（近似最近邻）索引。** 百万库线性遍历不可承诺响应时间（Lap 同样未解决，属共同短板，但本项目目标库更大，需优先）。
13. **每库扫描排除 / 扫描预览缺失。** 大目录精细控制不足。
14. **UI 语言仅 2 种**（可选项，非关键）。

### P2（高风险 / 高成本，需专项设计）

15. **地图视图缺失。** 涉及地图图源选型与合规，含 GPS 元数据采集与聚类联动。
16. **文件操作闭环缺失：拖拽/粘贴导入、按日期组织导入、重复跳过、安全移动/复制/删除、文件系统同步。** 直接触碰用户文件，风险最高。
17. **复合资源不支持：RAW+JPEG/HEIC 配对、Apple Live Photo、Google Motion Photo。** 需先定义复合资源关系与文件操作语义。
18. **内置编辑缺失（裁剪/旋转/翻转/缩放/基础调整）。** 需定义"写回原图"还是"导出副本"。
19. **格式广度不足（Lap 60+）。** 涉及解码器接入成本。
20. **平台缺口：无 Linux 构建、无壁纸设置、外部应用集成单薄。**

## 四、本项目的相对优势（不要在更新中丢掉）

- **Web / 局域网 / 公网访问 + 移动端适配**：Lap 完全没有，是本项目差异化护城河。
- **视频能力**：HLS 转码 + 多种字幕格式，强于 Lap。
- **人脸识别闭环**：分组/命名/合并/纠正 + 标准/严格阈值，功能面强于 InsightFace 裸用。
- **感知哈希视觉相似**：在精确哈希去重之外多一层近似查重。
- **MIT 许可**：商用与二次分发友好度高于 GPL-3.0。

结论：更新计划应"补组织层 + 补文件层"，同时持续强化 Web/远程与 AI 这两个已有优势。

## 七、一句话总结

本项目在 **AI 与远程访问**上已领先 Lap，真正的差距在 **组织元数据（评分/标签/集合/智能相册）** 与 **文件操作闭环（导入/移动/删除/复合资源）**。更新顺序：**先对齐与记录（1.2.0），再补组织层（1.3.0–1.4.0），再补地图（1.5.0），最后谨慎推进文件操作与复合资源（1.6.0+）**，同时持续强化 Web/远程与 AI 两项既有优势。
